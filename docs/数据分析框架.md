# 跨境电商数据分析框架

> 巴西市场 · TikTok + Shopee · BRL 计价 · 2026年5月

## 设计原则

**下钻路径**：看到问题 → 定位渠道 → 找到人 → 排查根因

每一层面向特定业务角色，从宏观到微观、从结果到原因逐层递进。

---

## 第1层：营收总览

**回答**：今天我们怎么样？

| 指标 | 口径 | 刷新频率 |
|------|------|----------|
| 今日/昨日订单量 | COUNT orders WHERE pay_time 在中国时区内 | 页面加载时 |
| 今日/昨日销售额 | SUM total_amount 同上 | 页面加载时 |
| 本月/上月订单量 + 销售额 | 同上，按月取范围 | 页面加载时 |
| GMV (近6月趋势) | SUM total_amount GROUP BY YYYY-MM | 页面加载时 |
| 客单价 AOV | total_amount / order_count | 页面加载时 |

**数据来源**：`public.orders`（千易ERP同步）

**对接角色**：管理层 / 运营负责人

---

## 第2层：渠道分析

**回答**：钱从哪个平台来的？

| 指标 | 口径 | 刷新频率 |
|------|------|----------|
| 平台 GMV 占比 | SUM total_amount GROUP BY platform | 与第1层同步 |
| 平台订单量月对比 | COUNT orders GROUP BY YYYY-MM, platform | 同上 |
| 平台 AOV 对比 | AVG total_amount GROUP BY platform | 同上 |

**数据来源**：`public.orders.platform`（TIKTOK / SHOPEE）

**对接角色**：渠道运营 / 投放负责人

**开发方向**：
- 当 platform 字段新增 TikTok Shop 等子渠道时，需增加细分维度
- 未来若接入广告 ROAS 数据，本层天然承接"投放效果 → GMV"归因

---

## 第3层：运营者分析

**回答**：谁做得好，谁需要帮忙？

| 指标 | 口径 | 刷新频率 |
|------|------|----------|
| 运营者 GMV 排行 | SUM orders.total_amount JOIN shop_operators | 与第1层同步 |
| 运营者订单量排行 | COUNT orders JOIN shop_operators | 同上 |
| 人均店铺数 | shops per operator | 页面加载时 |
| 人均 GMV | GMV / operator_count | 页面加载时 |

**数据来源**：`internal.shop_operators`（店铺-运营者绑定）JOIN `public.orders` ON shop_id

**对接角色**：运营负责人 / HR 绩效

**开发方向**：
- 当前 14 人全为巴西市场；后续台湾市场人员加入后，需按 market 维度拆分
- 运营者绑定数据来自 Excel 导入；未来需开发运营者管理后台（`/internal/admin` 已有基础 CRUD）
- 绩效目标值需新增 `internal.operator_targets` 表（月 GMV 目标），实现 vs 目标对比

---

## 第4层：订单健康度

**回答**：表面数字好，底层有没有隐患？

| 指标 | 口径 | 刷新频率 |
|------|------|----------|
| 订单状态分布 | COUNT GROUP BY status | 与第1层同步 |
| 退货率 | COUNT return_orders / COUNT orders × 100% | 同上 |
| 退货金额占比 | SUM return_orders.total_amount / SUM orders.total_amount | 同上 |
| 入库/出库异常 | ASN/ODO 状态为 CLOSED/DELETED 的占比 | 同上 |

**数据来源**：
- `public.orders.status`
- `public.return_orders`（退货单）
- `public.asns`（入库单）
- `public.odos`（出库单）

**对接角色**：仓储 / 客服 / 品控

**开发方向**：
- `return_orders` 目前 0 行（需确认千易退货单是否已对接）
- `asns` / `odos` 目前数据量极少，需确认是否已在千易开启自动同步
- 未来需新增 `internal.quality_issues` 表记录品控问题（破损、错发等），关联到具体 SKU 和运营者

## 广告费用分析

### 数据来源

千易无独立广告 API，广告费嵌入在各平台交易明细报表中：

| 平台 | 字段 | 含义 | API |
|------|------|------|-----|
| TikTok | `feeAffiliateAdsCommissionAmount` | 达人广告佣金 | `QUERY_TIKTOK_V2_TRANSACTION_DETAIL_LIST` |
| TikTok | `feeAffiliateCommissionAmount` | 达人佣金 | 同上 |
| TikTok | `feeAffiliatePartnerCommissionAmount` | 达人伙伴佣金 | 同上 |
| TikTok | `udf12` / `udf18` | 合作推广服务费 / TAP广告佣金 | 同上 |
| Shopee | `udf7` | 广告托管或技术支持费用 | `QUERY_SHOPEE_TRANSACTION_DETAIL_LIST` |
| Shopee | `orderAmsCommissionFee` | AMS佣金 | 同上 |
| Lazada | `affiliateAdsCommission` | 联盟广告费 | `QUERY_LAZADA_TRANSACTION_DETAIL_LIST` |

> 注意：这些是扣费账单，非投放报表。无素材级/达人级/计划级明细。Ads API 对接列入远期 TODO。

### 指标体系

**第1级：费用总量（按月、按平台）**

| 指标 | 公式 |
|------|------|
| 广告总支出 | `SUM(所有广告费用字段)` |
| 达人佣金（TikTok） | `SUM(feeAffiliateAdsCommission + feeAffiliateCommission)` |
| 技术服务费（Shopee） | `SUM(udf7 + orderAmsCommissionFee)` |

**第2级：效率指标**

| 指标 | 公式 | 健康阈值 |
|------|------|----------|
| 广告费用率 | `Ad Spend / GMV × 100%` | <15% 健康 / 15-25% 警告 / >25% 危险 |
| 达人佣金占比 | `Affiliate Cost / Ad Spend × 100%` | 反映达人依赖度 |
| 边际广告效率 | `ΔGMV(MoM) / ΔAd Spend(MoM)` | >1.0 增量投放有效 |
