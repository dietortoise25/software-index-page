# 运营负责人变动审批 — 模板定义

> 三方审批模式：表单和审批流由系统 API 创建，数据存储在我们的数据库，飞书负责审批操作和通知。

## 为什么用三方审批而不是原生审批

| | 原生审批 | 三方审批 |
|---|---|---|
| 表单字段 | 飞书后台手动配置，静态下拉 | **API 创建，数据来自我们的数据库** |
| 审批人 | 飞书后台固定设置 | API 动态指定 |
| ID 传递 | 飞书表单无动态数据源，ID 对不上 | **我们的 server 持有全部 ID，form 里既有文案也有 ID** |
| 双端发起 | 飞书端发起时下拉框无数据 | **网页端发起，飞书只做审批操作；飞书端点击链接跳转网页** |

一句话：表单和业务数据是我们管的，飞书只负责"审批这个动作"的 UI 和通知。

## 审批定义（API 创建）

通过 `POST /open-apis/approval/v4/external_approvals` 创建，只做一次：

```json
{
  "approval_name": "运营负责人变动审批",
  "description": "店铺主负责人任命、交接、修正审批",
  "form_fields": [
    { "field_name": "店铺名称", "field_type": "text" },
    { "field_name": "店铺ID", "field_type": "text" },
    { "field_name": "原负责人", "field_type": "text" },
    { "field_name": "新负责人", "field_type": "text" },
    { "field_name": "新负责人ID", "field_type": "text" },
    { "field_name": "变动类型", "field_type": "text" },
    { "field_name": "生效日期", "field_type": "text" },
    { "field_name": "变动原因", "field_type": "textarea" }
  ],
  "approver_list": ["ou_alan_open_id"]
}
```

> 审批人列表可以由发起人自选，或固定为指定人员（如 Alan）。具体在创建实例时指定。

## 审批实例（每次变动创建一个）

通过 `POST /open-apis/approval/v4/external_instances` 同步。Server 在用户提交时调用：

```json
{
  "approval_code": "ext_appr_xxxx",
  "instance_code": "change_20260516_001",
  "instance_title": "运营负责人变动 — shopee闫柳霖01 → 方正",
  "form_values": {
    "店铺名称": "shopee闫柳霖01（11958426739）",
    "店铺ID": "39591",
    "原负责人": "闫柳霖",
    "新负责人": "方正",
    "新负责人ID": "14",
    "变动类型": "交接",
    "生效日期": "2026-03-16",
    "变动原因": "闫柳霖转岗台湾业务线，巴西shopee全线交接给方正"
  },
  "task_list": [
    {
      "task_id": "task_001",
      "user_id": "ou_alan_open_id",
      "status": "PENDING"
    }
  ]
}
```

**关键设计**：`form_values` 里的"店铺ID"和"新负责人ID"字段在飞书端显示为只读，但 webhook 回调时完整返回。这样 ID 永远不会丢。

## 飞书端的审批卡片

审批人在飞书收到的通知卡片：

```
┌──────────────────────────────────────────┐
│  📋 运营负责人变动审批                      │
│                                          │
│  发起人：运营主管 (Alan)                    │
│                                          │
│  店铺名称：shopee闫柳霖01（11958426739）    │
│  原负责人：闫柳霖                           │
│  新负责人：方正                             │
│  变动类型：交接                             │
│  生效日期：2026-03-16                       │
│  变动原因：闫柳霖转岗台湾业务线...            │
│                                          │
│    [同意]  [驳回]  [转交]                  │
└──────────────────────────────────────────┘
```

审批人点击同意/驳回后，飞书 webhook 将状态变更推送给我们的 server。

## 双端发起

| 端 | 操作 | 说明 |
|---|---|---|
| **网页端** (`/internal/admin`) | 发起审批 | 在管理页面选店铺/运营者（下拉框数据来自 DB），提交后 server 调创建实例 API |
| **飞书端** | 审批操作 | 收到审批通知 → 点击同意/驳回/转交 → webhook 回调我们的 server |

飞书端不能直接"发起"，但可以提供一个入口链接跳转到网页端发起。
