# 运营数据维护方案

> 技术方案 + 用户故事 · 2026年5月

## 要解决的问题

运营业绩归属规则依赖"主负责人时间线"数据，但这类人事变动数据不存在于千易 ERP 中，需要独立维护。维护过程中要保证：**数据不被篡改、每笔变动可追溯、变动需审批**。

---

## 数据模型

### shop_operators 表（扩展）

在现有店铺-运营者关联表上增加三个字段：

| 字段             | 类型 | 说明                                      |
| ---------------- | ---- | ----------------------------------------- |
| `is_primary`     | 布尔 | 是否为主负责人（每店同时只有一人为 true） |
| `effective_from` | 日期 | 开始负责日期                              |
| `effective_to`   | 日期 | 结束负责日期（null = 至今）               |

### shop_operator_changes 表（新增）

变动记录表，每一条变动都永久保存，不可删除：

| 字段             | 说明                           |
| ---------------- | ------------------------------ |
| `operator_id`    | 哪个运营者                     |
| `shop_id`        | 哪家店铺                       |
| `change_type`    | 变动类型：任命/交接/修正       |
| `effective_from` | 从哪天生效                     |
| `effective_to`   | 到哪天结束                     |
| `submitted_by`   | 谁提交的                       |
| `status`         | 状态：待审批 / 已通过 / 已驳回 |
| `approval_id`    | 飞书审批单号                   |
| `reason`         | 变动原因（必填）               |
| `submitted_at`   | 提交时间                       |
| `approved_at`    | 审批通过时间                   |

---

## 审批流程

### 为什么需要审批

- **防篡改**：任何涉及业绩归属的变动，必须经过第二人确认
- **可追溯**：每条变动对应一张审批单，人事/运营可随时查阅
- **标准化**：变动原因必填，杜绝"随意改"的口头交接

### 飞书审批集成

飞书自带审批功能，无需自建。流程如下：

```
运营主管提交变动
  → 飞书审批推送到审批人（如 CEO/人事）
    → 审批通过 → 系统自动写入 shop_operators
    → 审批驳回 → 变动不生效，记录保留
```

审批通过后，系统通过飞书 Webhook 回调自动更新数据库，全程无需人工操作数据库。

## 用户故事

### 故事 1：任命新主负责人

**场景**：一家新店铺需要指定主负责人。

1. 运营主管打开内部管理页面（/internal/admin）
2. 在"店铺绑定"中点击某店铺的"任命主负责人"
3. 选择运营者，填写生效日期和原因（如"新店开业，闫柳霖全面负责"）
4. 提交 → 飞书审批推送到审批人
5. 审批通过 → 该店铺的 `is_primary` 自动设为 true，旧主负责人自动失效

### 故事 2：店铺交接

**场景**：店铺 A 从闫柳霖交接给方正，3 月 16 日生效。

1. 运营主管进入管理页面，选择店铺 A
2. 点击"交接"，选择新负责人"方正"，选择生效日期"2026-03-16"
3. 填写原因（如"闫柳霖转岗，方正接手巴西全线"）
4. 提交 → 飞书审批
5. 审批通过后，系统自动：
   - 闫柳霖的 `effective_to` 设为 2026-03-15
   - 方正的 `effective_from` 设为 2026-03-16，`is_primary` = true
   - 两人在 3 月的业绩按天数自动分配

### 故事 3：修正历史数据

**场景**：发现 1 月份的负责人记录有误，需要修正。

1. 运营主管进入"变动记录"页面
2. 找到那条历史变动，点击"申请修正"
3. 填写修正后的信息 + 原因（如"1 月实际负责人为黄泳桐，录入失误"）
4. 提交 → 飞书审批
5. 审批通过后，系统更新记录并重新计算历史业绩

### 故事 4：查看变动历史

**场景**：人事经理想知道某家店铺过去一年换了几任负责人。

1. 打开"店铺负责人时间线"页面
2. 选择店铺，显示完整时间线：谁从什么时候负责到什么时候
3. 点击任意一段，显示：谁提交的、谁审批的、审批单号、原因
4. 可以导出 Excel

## 界面位置

所有操作集成在现有 `/internal/admin` 页面，新增第四个 Tab：

```
内部管理
├── 分组管理
├── 人员管理
├── 店铺绑定
└── 负责人管理  ← 新增
```

负责人管理 Tab 包含：

- 列表视图：每家店的当前主负责人 + 历史时间线
- 操作按钮：任命 / 交接 / 查看历史
- 筛选：按运营者、按分组、按店铺

## 防篡改与审计

| 机制           | 说明                                   |
| -------------- | -------------------------------------- |
| **审批必过**   | 数据库不接受非审批的 is_primary 修改   |
| **永久日志**   | `shop_operator_changes` 表只增不删不改 |
| **操作人记录** | 每条变动记录提交人与审批人             |
| **原因必填**   | 变动原因不能为空                       |
| **前后对比**   | 审批单中自动附带变更前后的数据对比     |
