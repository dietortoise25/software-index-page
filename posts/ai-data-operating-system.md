## 一、系统定位

这个系统不是传统 BI（Business Intelligence）平台。

传统 BI 的核心是：

```text
人 -> 打开 Dashboard -> 查看图表 -> 思考问题
```

而真正高效的数据系统应该是：

```text
系统发现问题
-> 主动解释原因
-> 给出建议
-> 支持直接执行动作
```

因此，本系统的核心定位是：

# 一个事件驱动（Event-driven）的 AI 数据操作系统

目标：

* 持续感知业务状态
* 自动发现异常
* 自动生成解释
* 辅助甚至自动执行决策
* 降低企业对"人工分析"的依赖

---

## 二、核心设计理念

### 1. Push 优于 Pull

传统 BI 是 Pull 模式：

```text
用户主动打开系统看数据
```

问题：

* 老板不看 Dashboard
* 运营不会主动研究数据
* 数据系统长期闲置

因此：

# 数据系统应该主动推送信息

例如：

```text
ROI下降23%

原因：
- TikTok CPM上涨
- 女性用户转化下降

建议：
- 降低美国广告预算20%
- 转向Google Shopping
```

系统不仅告诉用户：

"发生了什么"

还需要解释：

"为什么发生"
"应该怎么办"

### 2. 数据系统的本质不是报表

数据系统真正的演化方向：

| 阶段            | 能力        |
| ------------- | --------- |
| Observability | 看发生了什么    |
| Diagnosis     | 分析为什么发生   |
| Prediction    | 预测未来会发生什么 |
| Decision      | 给出决策建议    |
| Automation    | 自动执行动作    |

Dashboard 只是其中最基础的一层。

### 3. 系统应该围绕 Event（事件）设计

而不是围绕 Dashboard 设计。

所有业务行为都应抽象为 Event：

```text
order_created
inventory_low
roi_drop
refund_abnormal
payment_failed
```

然后：

```text
Event
-> 数据处理
-> AI解释
-> 动作执行
-> 通知用户
```

这样系统才能真正扩展。

## 三、整体架构设计

### 系统架构

```text
Trigger Layer（触发层）
    ↓
Data Pipeline（数据处理层）
    ↓
Analysis Engine（分析引擎）
    ↓
AI Explanation Layer（AI解释层）
    ↓
Action Layer（动作层）
    ↓
Client Layer（客户端层）
```

## 四、Trigger（触发机制）设计

### 1. 定期触发（Scheduled）

固定时间自动运行。

**场景**：日报、周报、月报、GMV统计、广告ROI日报

**特点**：自动化程度高、模板化强、强调稳定性

### 2. 专项分析触发（Ad-hoc）

因为业务问题而启动分析。

**场景**：为什么销量下降？为什么ROI暴跌？为什么退款增加？

**特点**：非标准化、高度依赖业务理解、偏认知型工作

### 3. 预警触发（Alert）

指标异常自动报警。

**场景**：ROI低于阈值、库存不足、API错误率飙升、支付异常

**特点**：强实时性、高业务价值

### 4. 用户行为触发（Event-driven）

用户行为发生后立即分析。

**场景**：下单、注册、退款、浏览商品

**后续动作**：推荐系统、CRM打标签、自动营销

### 5. AI 对话触发（Conversational）

用户通过自然语言提问。

```text
为什么今天转化率下降？
```

系统自动：解析问题 → 生成SQL → 查询数据 → 返回解释

## 五、客户端设计

系统不应该只有一个客户端，而应该是 **多入口 + 一个统一数据中枢**。

---

## 六、客户端分层设计

### 1. 飞书 / Slack（主工作入口）

这是最重要的入口。

原因：用户已经长期在线、天然支持通知、支持机器人、支持审批与交互、支持 @人

#### 飞书中的核心功能

**（1）异常预警**

```text
ROI下降23%

主要原因：
- CPM上涨
- CTR下降

建议：
[暂停广告]
[查看分析]
```

重点：不是"提醒"，而是 **"提醒 + 解释 + 动作"**

**（2）AI经营日报**

不是PDF，而是 AI 自动总结的经营摘要：

```text
今日经营摘要：

GMV +12%
利润 -5%

主要原因：
冷冻虾采购成本上涨。
```

**（3）ChatBI**

用户直接提问："为什么今天销量下降？" → 系统自动分析并解释。

## 七、Web App 设计

Web App 用于数据分析师、高级运营、管理层。

### 核心能力

1. **Dashboard**：基础图表能力
2. **Drill-down**：支持逐层下钻（GMV → 地区 → SKU → 广告组 → 用户画像）
3. **SQL Playground**：高级用户直接查询数据（类似 Metabase、Superset）
4. **AI Copilot**：右侧 AI 助手，解释异常、生成周报、找出异常SKU

---

## 八、AI Chat：未来统一入口

长期来看，Chat 会逐渐吞掉传统 BI。

因为人类更擅长说话、提问、对话，而不是点 Dashboard、自己找图表。

```text
最近利润为什么下降？
```

AI：

```text
主要原因：

1. 牛肉采购成本上涨
2. TikTok ROAS下降
3. 高利润SKU缺货
```

---

## 九、AI Explanation Layer（最关键）

这是整个系统未来最核心的部分。

传统系统：`数据 -> 人解释`
未来系统：`数据 -> AI解释 -> 人决策`

AI需要：自动识别异常、自动关联原因、自动生成经营语言、自动给出建议

---

## 十、Workflow & Automation

系统最终不只是"分析"，而是 **自动执行动作**。

例如：

```text
ROI低于1.5
-> 自动暂停广告
-> 通知运营
```

```text
库存不足
-> 自动通知采购
```

## 十二、MVP（最小可行产品）

建议第一阶段：**「飞书 AI 数据助手」**，不要一开始做复杂 BI 平台。

### MVP 功能

1. **自动日报**：每天发送 GMV、ROI、Top SKU、异常变化
2. **异常预警**：ROI低于1.5自动报警
3. **AI问答**："为什么今天销量下降？"

---

## 十三、系统最终形态

最终，系统会变成企业的 **"数字神经系统"**，具备：

* 实时感知
* 自动分析
* 预测未来
* 提醒异常
* 自动执行

而 Dashboard 只是其中最不重要的一层。
